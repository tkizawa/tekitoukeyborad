# 適当キーボード (TekitouKeyborad)

**適当キーボード (TekitouKeyborad)** は、任意のアプリケーションで選択したテキストをショートカットキーひとつで **Microsoft Foundry Local** に渡して文章校正し、クリップボードへ格納（または自動貼り付け）する Windows 常駐型アプリケーションです。

## 主な特徴

- **システムトレイ常駐 & グローバルショートカット起動**
  - 「設定」→「動作・表示設定」の「Windows起動時に自動起動する（サインイン時）」を選び、「設定を保存」で自動起動を登録・解除できます。初期状態はオフで、現在のユーザーのみに適用されます。
  - 自動起動はスタートアップフォルダーのショートカットで管理し、インストーラーからの登録とも連動します。画面を出さずに常駐させたい場合は「アプリ起動時にシステムトレイへ最小化して開始する」もオンにしてください。実行ファイルは移動・削除しないでください。
  - デフォルトのショートカットキー（`Ctrl + Alt + K`、設定画面から自由に変更可能）を押すだけで、選択中のテキストを取得して校正します。
  - 事前の `Ctrl + C` は不要です。文字を選択したままショートカットを押し、すべてのキーを離してください。キー解放は最大2秒、コピー完了は最大1.5秒待機します。
  - クリップボードの遅延描画に対応し、キー解放待ち・入力先変更・コピー未確認などの失敗理由を通知します。
  - メモ帳などで `Alt` キーの解放時にフォーカスが入力欄へ戻る動作に対応し、同じウィンドウ・プロセス・スレッドであることを確認してからコピー先を確定します。コピー送信後と自動貼り付け時は、入力欄の一致も確認します。
- **Microsoft Foundry Local によるオフラインAI校正**
  - `Microsoft.AI.Foundry.Local` SDK を内蔵し、ローカル環境で AI モデルのダウンロード・メモリロード・推論を実行します。
  - `foundry service` などの OpenAI 互換ローカルエンドポイントへの HTTP 接続モードにも対応しています。
- **フォーカスを奪わないトースト通知 & 自動貼り付けオプション**
  - 画面右下に校正前後のプレビュー通知を表示し、クリップボードへ自動でコピーします。設定により校正完了後に自動で `Ctrl + V` 貼り付けを行うことも可能です。
  - 選択テキストのコピーによるクリップボード更新を確認できない場合は、以前のクリップボード内容を校正しません。
  - 自動貼り付け直前に元のウィンドウ・入力先と結果のクリップボード内容を確認します。一致しない場合や修飾キーが押されている場合は、貼り付けを中止して通知します。別のウィンドウへ強制的にフォーカスを戻すことはありません。
  - 入力先の確認にはWindowsのフォーカス情報を使用します。同じ入力欄内でのカーソル・選択範囲の変更などは検知できないため、自動貼り付けを使う場合は完了まで対象の文章を操作しないでください。
  - コピーやキー送信に失敗した場合はエラーを表示し、自動貼り付けを行いません。校正結果はアプリ画面から再コピーできます。
- **校正プロンプトのプリセット & カスタマイズ**
  - 「標準校正」「ビジネス丁寧語」「簡潔・要約」のプリセットに加え、独自のシステムプロンプトを設定できます。
  - ローマ字の日本語には「設定」→「校正プロンプト設定」で「ローマ字 → 日本語」を選び、「設定を保存」を押してください。漢字・かな交じりの自然な日本語に変換して校正します（例: `yorosiku onegaisimasu` → `よろしくお願いします。`）。空白のない入力やヘボン式・訓令式、日本語との混在にも対応するようAIへ指示します。
  - ローマ字プリセットでは固有名詞・略語・URL・メールアドレスなどの綴りを維持するよう指示します。変換精度は使用モデルと文脈によって異なります。
  - 全文を変換できる小文字のローマ字は、アプリ側でかな読みを作り、原文と読みの両方をAIへ渡して漢字・文法を校正します。固有名詞・日本語との混在や未対応の綴りは原文のままAIへ渡し、部分変換による破損を避けます。画面・履歴には元のローマ字文を残します。
  - 通常の英文校正には「標準校正」を選んでください。既存のプリセットや保存済みのカスタム指示は変更せず、ローマ字プリセットはFoundry Local SDK・OpenAI互換エンドポイントの両方で利用できます。
- **多言語（日本語・英語） & テーマ（ライト・ダーク）連動**
  - Windows の表示言語設定およびアプリのテーマ設定に連動して自動的に表示を切り替えます。

## 動作環境

- Windows 10 / 11 (x64)
- .NET 10.0

## ビルド・起動

```powershell
dotnet run -r win-x64
```

`Tests` と `scratch` 配下の補助プロジェクトは、生成ファイルも含めて本体のビルド対象から除外しています。

### スタンドアロンインストーラー

Windows x64向けのEXEを `Installer` に作成します。アプリのバージョンをファイル名に含め、.NETランタイムとFoundry Localが必要とするVisual C++ランタイムDLLを同梱します。配布先で.NETを別途インストールする必要はありません。AIモデルは含まれず、初回利用時に別途ダウンロードします。

発行コマンドは以下です。発行後、正規のMicrosoft Visual C++ x64ランタイムから `msvcp140.dll`、`msvcp140_1.dll`、`msvcp140_atomic_wait.dll`、`vcruntime140.dll`、`vcruntime140_1.dll` を発行先に配置し、Inno Setupで `setup.iss` をコンパイルしてください。

```powershell
dotnet publish .\TekitouKeyborad.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:PublishTrimmed=false -o .\publish\win-x64
```

### 校正時に KV キャッシュのメモリ確保エラーが出る場合

Foundry Local SDK 2.2.1 では、短文でもモデルのコンテキスト長全体に対応する KV キャッシュを確保しようとする場合があります。`Could not allocate the key-value cache buffer` が表示される場合、最大出力トークン数を減らすだけでは解消しません。

現在の回避策は、アプリと同じモデルを使用するプロセスを終了し、モデルキャッシュ内の `genai_config.json` をバックアップしてから、`model.context_length` と `search.max_length` を両方とも `4096` に変更して再起動することです。既定のキャッシュは `%USERPROFILE%\.TekitouKeyborad\cache\models` 配下です。

- 入力・システムプロンプト・出力を合わせた上限が4096トークンになります。長文は分割してください。
- 同じキャッシュを使う他のアプリにも影響します。元に戻す場合は、関連プロセスを終了してバックアップを復元してください。
- モデルの再ダウンロード・更新で設定が元に戻る場合があります。
- SDK 2.2.1 では、リクエストの `AdditionalOptions` に `max_length` を指定しても、この確保サイズは変更できません。

## 設定ファイルの保存先

- `%LocalAppData%\TekitouKeyborad\settings.json`
- 未設定のウィンドウ位置は JSON の `null` として保存し、次回表示時は画面中央に配置します。既存の数値座標も引き続き読み込めます。

## 回帰テスト

追加パッケージ不要の回帰テストを、以下のコマンドで実行できます。

```powershell
dotnet run --project .\Tests\RegressionTests.csproj -c Release -r win-x64
```

テストではOS操作を代替実装に置き換え、実際のクリップボード・キー入力や利用者の設定ファイルを変更せずに、取得失敗・貼り付け中止・リトライ・設定JSONの互換性を確認します。
自動起動のテストでは一時フォルダーに実際のショートカットを作成して、登録・更新・解除とリンク先を検証します。Windowsのスタートアップフォルダーは変更しません。
